# 搭搭不搭搭 0.1.6 生产发布

当前代码生产包，平台 linux/amd64，镜像 fit-or-not-backend:0.1.6。面向用户的更新说明见 [更新内容](changelog-0.1.6.md)，发布目录另附 UPDATE_NOTES.md。

## 变更

新增修补／重新识别描述的文字优化接口，结果仅回填描述，用户确认后才创建图片任务；不传图片，超时保留原输入。单件图片按原图及目标描述生成透明图，资料识别与图片处理并行；旧任务保存的遮罩继续支持复用。明确未发送的网络失败可重试，结果不确定的任务需确认后重新处理，复用已成功阶段和原输入，请求幂等防止重复排队。

衣橱新增未设置二级分类筛选，未完成照片在默认衣橱显示；提交识别后返回衣橱。更新处理状态展示，在衣物编辑、穿搭记录和未提交照片离开时提示。删除待核对衣物时同步维护录入状态，剩一件可按单品继续保存。

## 数据库迁移

本次新增 V16__deleted_import_members.sql，仅修正包含已删除成员且未确认／未取消的历史录入：全部成员已删除则取消录入，仅剩一件则转为单品并关闭保存套装；取消已无用的整套图任务或空录入任务。排队任务标记取消，运行中任务请求取消。原图、任务结果、剩余衣物资料及待核对状态保留。正常录入、已确认／已取消录入保持原样。

历史 V1–V15 SQL 校验和与 0.1.5 完全一致。API／worker 启动自动迁移至 V16。从 0.1.5 升级无需删表；用户、头像、微信身份、会话、邀请码、衣物、分类、出行清单及勾选状态、提醒结果和推荐缓存保留。

尚未执行历史 V8 的旧库首次启动仍会执行此前授权的一次性测试数据清理：保留用户资料、微信身份、头像资源及迁移历史，清空其余测试业务数据（含会话和邀请码），为已有账号重建 11 个一级分类，不预置二级分类。已有 V8 记录的数据库不会再次清理。保留 schema_migrations 和媒体卷。

## 部署

保留服务器现有 .env、Compose 项目名与媒体卷。停止旧 API／worker 后导入镜像，两处镜像标签均更新为 fit-or-not-backend:0.1.6，再重建；不要用包内空密钥模板覆盖生产 .env。

```sh
docker compose -f compose.yml stop api worker
docker load -i fit-or-not-backend-0.1.6-linux-amd64.tar.gz
docker compose -f compose.yml up -d --force-recreate --wait
docker compose -f compose.yml logs --tail=100 api worker
```

本次没有新增必填环境变量，沿用原配置。配置示例中的数据库密码、签名密钥、AppID、AppSecret、提醒模板 ID 和外部 API 密钥保持空值，部署时填入服务器 .env；提醒模板使用微信后台已添加的模板，消息环境为 formal。PUBLIC_BASE_URL 与小程序 API 地址需保持对应。
