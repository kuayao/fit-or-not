## 工程目录建议

```text
fit-or-not/
  miniprogram/          微信原生页面、组件、接口和资源
  server/
    src/               Express 业务代码、Node.js worker 与图像服务调用
    migrations/        有序 SQL 迁移
  deploy/              容器、Nginx、环境示例和备份操作
  docs/design/         当前设计包、原型、图稿与验证记录
```

目录随实际模块创建，不预生成无实现的服务层/仓储层。业务应用与任务 worker 共用 Node.js 依赖，各有启动命令。

## 验证顺序

1. 静态检查：文件路径、类型、接口字段、迁移约束和版本对应。
2. 独立环境：PG 实际读写、鉴权/归属、媒体与任务状态，使用真实实现。
3. 微信工具：原生编译、组件/SVG、路由、表单、页面状态。
4. 真机：相册/拍照、键盘、登录、后台恢复、图片加载、手势与安全区域。
5. 目标服务器：图片后处理峰值、任务排队、3个用户并行访问、磁盘与恢复演练。
6. 外部服务：真实供应商沙箱或小额授权请求，记录调用与费用；未取得授权的付费操作留待用户发起。

## 实施纪律

- 每次改动围绕当前步骤的可运行结果，按照 AGENTS.md 给出具体文件范围和验证方式。
- 遇到新依赖或模型不达标，提交证据和调整建议，不将未实现功能标记完成。
- 本设计中的资源/效果阈值是验证目标；实测不达标时需要调整方案或与用户修改目标。
- 工期在模型验证和服务商选定后估算；当前不以未经验证的天数作交付承诺。
