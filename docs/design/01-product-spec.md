# 产品需求与完整功能范围

## 目标与使用者

搭搭不搭搭 帮助使用者知道自己有什么衣服、保存适合自己的组合、回顾实际穿着。产品主要面向女生，目前使用者为本人和朋友共 2–3 人；每个人拥有独立数据。完整交付覆盖下表，实施顺序不改变范围。

成功标准：一件衣服可从照片录入并完成整理；一套搭配可保存并记录到日历；统计可追溯到真实记录；图像任务执行时正常浏览仍可用。

## 衣物录入与字段

| 字段 | 约束与默认值 |
| --- | --- |
| 图片 | 必填；一张衣物主图，可增加细节图；图像任务前保留原图 |
| 分类 | 保存为正常衣物时必填；分类未确认的上传项留在录入草稿 |
| 名称 | 可选；为空时按确认后的分类生成可编辑名称 |
| 颜色 | 可多选，允许“多色”；AI 识别提供建议 |
| 季节 | 可多选春/夏/秋/冬/四季；允许不填 |
| 场景/风格 | 用户自己的标签，可多选 |
| 品牌/尺码/面料/备注 | 可选文字；品牌等不由图片分类模型直接断言 |
| 购买价格 | 可选非负人民币金额，保存到分；空值与 0 元不同 |
| 购买日期 | 可选日期，不能晚于用户当地当前日期 |
| 收藏/状态 | 默认未收藏；草稿、正常、归档三态 |

图片设计限制：单文件最多 10 MB、最多 2400 万像素；允许 JPEG、PNG、WebP；批量一次最多 20 张。客户端提供选择与压缩，服务端仍校验文件内容和解码尺寸。HEIC 通过客户端/平台转为支持格式后上传。以上是产品初始限制，需用微信真机图片验证。

新增草稿先上传图片，用户点击“抠图与识别”后在录入页等待结果，也可直接手动填写分类并保存。处理期间文字资料可继续填写，结束后恢复保存。候选结果由用户点选填入表单，已有手动修改保持优先。用户可对比并选择原图或处理图，抠图结果作为独立资产保存，最终点击保存写入衣橱。

## 衣橱与整理

- 搜索名称、品牌和备注；分类、颜色、季节、标签及收藏条件可以组合。
- 默认按创建时间倒序，支持最近穿着、穿着次数及购入价格；排序用 ID 稳定补序。
- 批量操作包括改分类、加减标签、归档；永久删除逐件说明引用影响。
- 归档后从默认衣橱隐藏，可恢复；历史搭配与日历保留引用并显示“已归档”。
- 无引用衣物可以永久删除；被搭配、日历或清单引用时返回引用清单，用户先处理引用或选择归档。
- 图片未处理、处理失败、空衣橱、筛选无结果分别有明确呈现。

## 搭配与画布

- 从正常衣物中选择 1–12 件；一个搭配内同一衣物只出现一次。
- 自动排版为默认起点，允许拖动、缩放、旋转、调整前后层级和更换背景色。
- 画布采用归一化坐标，尺寸比例 3:4；编辑时可撤销本次会话操作，保存后再退出。
- 记录衣物 ID、相对位置、尺寸、角度和层级；输出图由服务端按相同布局生成。
- 支持名称、场景、季节、备注、收藏；默认私有。
- 导出搭配图片属于用户主动操作；上身照片不会自动包含在普通搭配导出图中。

## 穿搭记录与统计口径

- 一条记录对应一个日期、一个场景和一组实际穿着衣物；可来自搭配或直接选择衣物。
- 同一天可以记录多条，但同一衣物在同一日期的“穿着次数”只记 1 次。
- 日期使用用户时区的自然日；当前默认时区为 Asia/Shanghai。未来日期不计实际穿着，录入界面限制到当天。
- 日历保存时复制当时的衣物集合及可读名称。以后修改搭配，不改变已有穿搭记录。
- 修改或删除记录后，以现存有效记录重新计算统计；保存搭配本身不增加次数。
- 活跃衣物数统计正常状态；分类占比以活跃衣物为分母。购入金额只汇总已填写的价格，并显示有价格的样本数。
- 单次穿着成本 = 该衣物购买金额 / 其不同穿着日期数。0 次显示“尚未穿着”，无价格显示“未填写价格”。
- 少穿排行是记录结果，不是淘汰建议；未记录不等于实际未穿。所有统计注明计算范围。

## 图像识别与处理边界

- 识别与抠图由服务端 worker 调用 New API，识别资料与颜色提供可修改的建议。完整协议见[第三方抠图与衣物识别](11-ai-clothing-processing.md)。
- 单件、完整入镜、平铺或挂拍的照片是推荐输入；多人、多件叠放、遮挡严重的照片需要用户裁剪。
- 自动抠图结果可与原图比较并重新处理。无法得到可用结果时仍能用原图保存衣物。
- 任务状态包含等待、处理中、成功、失败、已取消；图像任务并发为 1。
- 用户发起处理后发送当前照片到已配置的第三方服务；识别与抠图分别记录结果，重试只补失败阶段。

## 外部智能能力

- 天气：优先自动获取微信位置，位置获取失败、授权拒绝或无法解析城市时自动改用用户请求来源 IP 识别大致城市；IP 无法识别时结束自动获取流程，用户可点击卡片城市手动选择。手选支持中文、拼音、地级市、县级市及区县，展示行政归属以区分同名地点，也可随时点击卡片城市切换。首页卡片显示实况天气、当前气温、湿度和风向风力，可手动刷新。展开查看今天、明天、后天的逐日预报，显示预报日期、白天/夜间天气、白天/夜间温度；实况和预报分别显示数据发布时间。请求失败时不把过期预报当作最新数据。天气采用高德服务，IP 自动识别使用仅支持国内 IPv4 的 v3 接口；搜索到地区不表示该地区一定有天气数据。
- AI 搭配：使用场景、天气和用户允许使用的衣物资料生成建议；结果中的衣物 ID 必须在本用户集合中。用户确认后保存。
- 虚拟试穿：展示将发送的照片及衣物、预计费用或收费规则、服务名称；用户发起后创建异步任务。
- 每位用户设日额度、应用设总额度，金额/次数上限由部署配置确定。配置缺失时无法发起付费任务。
- 超时、额度不足、供应商失败、拒绝处理分别展示；收费状态不明确时先查询任务，避免重复提交和重复扣费。
- AI 搭配与虚拟试穿的服务商和价格未定是交付依赖。交付验收必须验证真实服务，原型演示不能替代。

## 准入、导出与删除

- 已绑定成员直接微信登录。新成员输入服务端生成的一次性邀请码，绑定当前微信身份；邀请码只保存摘要，默认 72 小时过期。
- 服务端维护成员名单；默认人数上限 3，可由运营配置调整。邀请码创建、停用为维护者服务器操作。
- 业务数据按用户隔离。所有资源请求都校验登录用户，下载与图片同样受控。
- 导出为 ZIP：结构化 JSON/CSV 和本用户图片，说明字段与时区；下载链接短期有效，导出文件 24 小时清理。
- 注销需再次确认，立即撤销会话，异步清理本用户数据和文件；备份中的数据按保留周期到期清理。
- 备份建议保留最近 7 天，至少一份位于服务器之外。实际备份位置和容量为部署前必填项。

## 完整交付判定

F01–F13 均须具有实现、正常与异常路径验证及可追溯结果。外部服务尚未配置、图像效果尚未通过真实样本验证时，相应功能保持“待验证/待集成”状态，不能宣称完整产品已交付。
